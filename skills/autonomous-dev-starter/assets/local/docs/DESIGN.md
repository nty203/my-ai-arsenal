# Project design

## Stable purpose

Describe what the project must achieve and for whom.

## Invariants

1. List behavior that must not regress.
2. List security, compatibility, and data constraints.
3. Define what requires human approval.

## Completion signals

List observable outcomes and the commands or user flows that prove them. These define `PROJECT_COMPLETE`.

## Improvement signals

List measurable evidence the autonomous evaluator may optimize after planned work is exhausted: correctness, UX friction, performance, reliability, tests, accessibility, or maintainability. Subjective polish alone is not enough.
